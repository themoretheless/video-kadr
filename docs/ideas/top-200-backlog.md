## Корректность и A/V-синхрон (19)

1. 🐞 **[H·S]** Probe and store sample rate, channels, avg_frame_rate - ProbeInfo captures only duration/wh/fps/codecs, so the renderer can never detect VFR (r_frame_rate vs avg_frame_rate mismatch) or sample-rate/channel-layout differences that drive desync, leaving every sync fix blind. `backend/src/tools/mod.rs:23-31,218-243 (ProbeInfo, probe_video)`
2. 🐞 **[H·S]** Enforce speed bounds server-side to keep setpts and atempo paired - video_filters uses exact setpts=1/speed while audio_filters clamps atempo to 0.5-2.0; the backend never clamps req.speed, so an API request with speed 4.0 plays video at 4x but audio at 2x, total A/V desync. `backend/src/tools/args.rs:138-153,169-173; backend/src/handlers/mod.rs:476-497 (normalize_edit_geometry has no speed clamp)`
3. 🔧 **[H·S]** Add aresample=async=1 to absorb audio/video clock skew - No filter compensates when decoded audio and video timestamps diverge (common on yt-dlp merged streams); aresample=async=1 stretches/pads audio to track the video clock and prevents accumulating offset. `backend/src/tools/args.rs:158-189 (audio_filters), 192-206 (push_audio)`
4. 🔧 **[H·S]** Force CFR output with fps_mode=cfr on re-encode - Re-encodes pass through source VFR timing untouched; setting -fps_mode cfr (or -vsync cfr) on the video output guarantees evenly spaced frames so players keep audio locked, even when input was VFR. `backend/src/tools/args.rs:368-427 (push_video_codec), 208-215 (push_fps)`
5. 🐞 **[H·S]** Crop is not validated against source dimensions - crop x/y/w/h are emitted unchecked, so a rectangle larger than or outside the frame makes ffmpeg fail with a raw error instead of a clear validation message. `backend/src/tools/args.rs:75; backend/src/model.rs:199`
6. 💡 **[H·M]** Normalize VFR sources to CFR on import - Phone/yt-dlp clips are often variable-frame-rate; without a CFR pass on import every later trim/concat/speed op drifts audio against video progressively, the single largest desync source for a trim+concat tool. `backend/src/tools/mod.rs:189 (probe_video), backend/src/handlers/mod.rs:106`
7. 🐞 **[H·M]** Unify sample rate and channel layout before concat - build_concat_args atrims and concatenates audio segments with no aresample/aformat, so when segment boundaries land on differing decoded layouts the concat filter pads/drops samples and audio slips against video. `backend/src/tools/args.rs:431-521 (build_concat_args, atrim/concat)`
8. 🐞 **[H·M]** Sync-drift assertion tests for trim+speed+concat - args.rs tests only check string presence; nothing renders a real clip and asserts output audio duration equals video duration within tolerance, so any desync regression ships undetected for the core ops. `backend/src/tools/args.rs:551-972 (unit tests), backend/tests/render.rs`
9. 🐞 **[H·M]** Keyframe interactions with input-side trim (-ss) offset - Trim is applied as -ss before the filter graph, so filter-time t starts at 0 after the cut; keyframe times authored in source-time will be silently off by the trim start unless the compiler rebases them. `backend/src/tools/args.rs:240-247`
10. 💡 **[H·M]** Probe keyframe (GOP) positions via ffprobe packets - probe_video only reads duration/dims/fps/codecs, so the backend has no idea where keyframes are and cannot decide between copy and re-encode; adding a packet probe (-show_packets -skip_frame nokey) gives the keyframe timestamps every smart-render and snap feature depends on. `backend/src/tools/mod.rs:189-243`
11. 🐞 **[H·M]** VFR sources break PTS after trim+setpts in concat graph - The concat path applies trim+setpts=PTS-STARTPTS but never forces a constant frame rate, so a variable-frame-rate source (common from screen recorders / phones) yields drifting timestamps and progressive audio-video desync across stitched segments; a -vsync cfr / fps normalization before concat fixes it. `backend/src/tools/args.rs:444-466`
12. 🟡 💡 **[H·L]** Two-pass stabilization (vidstab detect + transform) - Self-contained two-pass vidstab fixes shaky handheld footage with a big perceived-quality win and no timeline dependency. `docs/ideas/round-13.md` **[частично: вышло, но на локальной сборке ffmpeg нет libvidstab, реальный рендер не проверен]**
13. 🔧 **[M·S]** Chain atempo for speeds outside 0.5-2.0 instead of clamping - atempo only accepts 0.5-2.0 so any future wider speed range silently mis-tempos audio; emitting chained atempo factors (e.g. atempo=2.0,atempo=2.0 for 4x) keeps audio matched to the setpts video time. `backend/src/tools/args.rs:169-173`
14. 🐞 **[M·S]** Add asetpts=PTS-STARTPTS reset after audio filters in single-pass - The single-pass audio chain never resets PTS after atrim-equivalent input trim, so when -ss yields a non-zero audio start timestamp the muxer may honor the offset and delay audio relative to the reset video stream. `backend/src/tools/args.rs:158-189 (audio_filters), 240-247`
15. 🔧 **[M·S]** Reset audio PTS on concat boundaries with asetpts already verified - Concat resets per-segment with asetpts=PTS-STARTPTS but applies no gap guard; inserting aresample=async between segments would close sub-frame audio gaps at each join that otherwise accumulate across many cuts. `backend/src/tools/args.rs:444-466 (per-segment atrim/asetpts/concat)`
16. 🔧 **[M·S]** Generate monotonic PTS for streams with broken timestamps - yt-dlp remuxes and some captures carry non-monotonic or missing DTS/PTS; adding -fflags +genpts on input lets ffmpeg rebuild a clean clock so trim and concat math is reliable rather than drifting on garbage timestamps. `backend/src/tools/args.rs:238-250 (input args), backend/src/tools/mod.rs:265-269 (run_ffmpeg cmd)`
17. 🐞 **[M·S]** Input -ss seek decodes from prior keyframe, not exact frame - Trim uses input-side -ss which on a re-encode is frame-accurate in modern ffmpeg but the start frame still depends on decoding from the preceding keyframe; there is no guarantee or test that the first output frame equals the requested timestamp, and no output-side -ss fallback for codecs/containers where input seek is imprecise. `backend/src/tools/args.rs:240-247`
18. 🐞 **[M·S]** Segment timestamps formatted to 3 decimals lose frame precision - format_secs and the concat trim graph print times as {:.3}, so a request for frame N at 59.94fps (e.g. 1.001s boundaries) rounds to the nearest millisecond and can land one frame early/late at every cut; round to the frame grid or pass more precision. `backend/src/tools/args.rs:444-454, backend/src/tools/args.rs:547-549`
19. 💡 **[M·S]** Aspect-locked crop with numeric input - 16:9/1:1/9:16 locks plus typed values close a real UX gap in the current free-rect crop. `docs/ideas/round-13.md`

## Безопасность (7)

20. 🐞 **[H·S]** ServeDir exposes entire storage including app.db and library.json - Audit #35: the static file route serves all of storage, so app.db and library.json are downloadable; move the DB out of the served tree and gate internal files. `backend/src/lib.rs (ServeDir ~54)`
21. 🐞 **[H·M]** SSRF guard only checks literal IPs, bypassable via DNS - Audit #33 verified open: validate_url parses host as a literal IP and skips the block check for any hostname, so a domain resolving to 169.254.169.254/loopback/RFC1918 (or a redirect) is allowed; must resolve and check all A/AAAA records. `backend/src/tools/net.rs:21-25 (validate_url literal-IP-only)`
22. 🐞 **[H·M]** No authentication on any endpoint - Audit #34: every route is unauthenticated, so exposing the service to a network gives anyone full import/edit/delete/file access; needs a token middleware before any exposure. `backend/src/lib.rs (router ~28-58)`
23. 🐞 **[H·M]** SSRF guard bypassed via DNS rebinding/redirects - validate_url only checks literal IPs while yt-dlp resolves the hostname itself, so a domain resolving to 169.254.169.254/loopback or an HTTP redirect to a private IP reaches internal services. `backend/src/tools/net.rs:10-47; backend/src/tools/mod.rs:103`
24. 🐞 **[H·M]** Sanitize keyframe values before embedding in ffmpeg expressions - Effect params are formatted with fixed precision today, but free-form keyframe-driven expression strings risk injecting filtergraph syntax; values must be numerically clamped/formatted, never string-concatenated, to avoid breaking or escaping the graph. `backend/src/tools/args.rs:108-134`
25. 💡 **[H·M]** Optional single-user auth token before exposure - No endpoint has authentication (lib.rs:30-57); any process on the host or network reaching the port can import, render, and delete files. `backend/src/lib.rs:28-58; docs/audit.md:77`
26. 🐞 **[H·M]** Resolve DNS in validate_url to close SSRF bypass - validate_url only blocks literal IPs (net.rs:21-25); a hostname resolving to 127.0.0.1/169.254.169.254 passes and yt-dlp then fetches it, defeating the guard. `backend/src/tools/net.rs:10-47`

## Надёжность и эксплуатация (15)

27. 🐞 **[H·S]** Keyframe-aware render cache key - render_cache_key hashes the serialized EditRequest; if keyframe arrays are added without stable serialization (ordering, float formatting) two identical animations can miss cache or two different ones can collide, returning a wrong render. `backend/src/handlers/mod.rs:255-259`
28. 🐞 **[H·S]** Cancelled/timed-out import leaves partial files - The import worker cleans up only on the Done::Cancelled branch and on Err, but a job cancelled while queued or a permit-closed path can leave <id>.part/<id>.info.json orphans that accumulate when FILE_TTL_HOURS=0. `backend/src/handlers/mod.rs:69-104`
29. 🐞 **[H·M]** yt-dlp grandchild ffmpeg orphaned on cancel/timeout - Audit #4 verified: run_with_progress only does child.start_kill(), so the ffmpeg spawned by yt-dlp survives cancellation, leaking CPU and a job slot; needs process_group(0) + negative-pgid kill. `backend/src/tools/mod.rs:303,347-348`
30. 🐞 **[H·M]** Upload bypasses the job semaphore (DoS) - upload_handler writes to disk and runs ffprobe on every request without acquiring jobs_semaphore, so many concurrent uploads can saturate disk/CPU unbounded while imports/edits are throttled. `backend/src/handlers/mod.rs:144-231`
31. 🐞 **[H·M]** Graceful software fallback on hw encoder failure - hw encoders fail on driver/device errors (no GPU, busy session, unsupported pix_fmt); run_ffmpeg has no retry, so a failed nvenc job dies instead of re-running with libx264. `backend/src/tools/mod.rs:258; backend/src/handlers/mod.rs:334`
32. 🐞 **[H·M]** Verify hw encoder actually works, not just listed - ffmpeg lists hevc_nvenc even with no GPU/driver present; a build that lists an encoder but fails at runtime would route every job to a dead path unless a one-frame smoke-encode confirms it. `backend/src/tools/mod.rs:48`
33. 🐞 **[H·M]** Graceful shutdown drains in-flight jobs, not just HTTP - main.rs:90-93 closes the HTTP listener on Ctrl-C but never awaits running download/render workers, so a SIGINT mid-render orphans the ffmpeg/yt-dlp child and leaves the job stuck non-terminal until the next restart marks it interrupted. `backend/src/main.rs:90-100`
34. 🐞 **[H·M]** No disk-space guard before download/render/upload - Nothing checks free space before writing GBs to sources/ or outputs/, so a full disk surfaces as a raw ffmpeg/IO error in job.error instead of a clean 'out of space' state, and a half-written output may be cached. `backend/src/handlers/mod.rs:166-185,327-359`
35. 🐞 **[H·M]** No SQLite migration framework; schema_version is dead - db.rs ships a single CREATE TABLE IF NOT EXISTS blob and writes projects.schema_version=1 but never reads PRAGMA user_version, so any future column/shape change has no upgrade path and will silently diverge or break an existing app.db. `backend/src/db.rs:18-48,25`
36. 🐞 **[H·M]** Upload bypasses the jobs semaphore (unbounded concurrent writes+probes) - upload_handler streams to disk and runs ffprobe inline on every request without acquiring jobs_semaphore, so N simultaneous large uploads each spawn an unthrottled disk write plus a blocking probe, bypassing the concurrency cap that protects renders/imports. `backend/src/handlers/mod.rs:144-231`
37. 🐞 **[M·S]** Health/startup check that storage and db are writable - Startup creates dirs but never verifies writability or free space (main.rs:24-25, audit #64/#195), so a read-only or full storage mount fails opaquely deep inside a render rather than at boot. `backend/src/main.rs:24-25`
38. 🐞 **[M·S]** BIND_ADDR parse failure silently falls back to 127.0.0.1 - Audit #51: a malformed BIND_ADDR is silently replaced with 127.0.0.1 and logs nothing, so a containerized server becomes unreachable with no clue why; parse strictly and fail fast. `backend/src/main.rs (BIND_ADDR parse ~84)`
39. 🐞 **[M·S]** All numeric env vars fail soft to defaults - Audit #52: env reads use .parse().ok().unwrap_or(default), so MAX_CONCURRENT_JOBS=0 or a typo silently becomes the default and misconfiguration goes unnoticed; validate and error on bad values via a single Config. `backend/src/main.rs (env parsing ~51-83)`
40. 🐞 **[M·S]** yt-dlp and ffmpeg unpinned in Docker (non-reproducible) - Audit #53: yt-dlp is pulled from releases/latest and ffmpeg from apt with no version pin, so builds are non-reproducible and a yt-dlp update can break progress parsing. `Dockerfile:9-13`
41. 🐞 **[M·S]** Backend runs as root with no USER/HEALTHCHECK/limits - Audit #54: the container runs as root and defines no USER, HEALTHCHECK, or resource limits, so a compromise has full container privileges and orchestration cannot detect health. `Dockerfile:8-20`

## Данные, модель, портативность (26)

42. 🐞 **[H·S]** Preserve original import URL/provenance on imported media - import_handler reads the title then deletes the .info.json sidecar (tools/mod.rs:119-128) and never stores the source URL, so a purged URL-import can never be re-fetched. `backend/src/tools/mod.rs:119-128`
43. 🐞 **[H·M]** Surface offline/missing media instead of silently hiding it - A missing source file vanishes from the library with no badge or warning, so the user cannot tell a clip went offline versus was deleted. `backend/src/library.rs:99-113`
44. 🐞 **[H·M]** TTL cleanup deletes files by mtime with no reference check - Audit #24 verified open: spawn_cleanup removes any sources/outputs file older than TTL by mtime, so it can delete a source under an active/queued render and orphan projects/jobs/cache entries. `backend/src/main.rs:103-130 (spawn_cleanup)`
45. 🐞 **[H·M]** Store source-file content hash on every media entry - MediaEntry (library.rs:12-29) has no checksum, so a file that moves, is re-encoded, or is replaced under the same UUID cannot be verified or relinked, and corruption is silent. `backend/src/library.rs:12-29`
46. 🐞 **[H·M]** TTL cleanup deletes source files a project still references - spawn_cleanup (main.rs:103-135) prunes sources/outputs purely by mtime with no reference check, so it can delete a source under a saved project and make it permanently offline. `backend/src/main.rs:103-135`
47. 🐞 **[H·M]** No SQLite migration mechanism - schema_version is written but never read and PRAGMA user_version is unused (db.rs:18-48); any future column change breaks every existing app.db with no upgrade path. `backend/src/db.rs:18-48`
48. 💡 **[H·M]** Project export to a portable .vproj bundle - Projects live only in storage/app.db as opaque video_json/edit_json blobs (db.rs:54-62) with no way to move a clip+recipe to another machine or back it up. `backend/src/db.rs:18-62; backend/src/handlers/projects.rs`
49. 💡 **[H·M]** Consolidate: copy all media used by a project into one folder - Editor-grade archiving needs a consolidate step that gathers every referenced source (and optionally the render-ready output) into a single tree; nothing in storage/ groups media by project today. `backend/src/library.rs:138-145`
50. 💡 **[H·M]** Re-import (re-download) a purged URL source from stored provenance - Once the original URL is stored, an offline URL-import could be re-downloaded with one click instead of the user re-pasting the link and losing the edit linkage. `backend/src/handlers/mod.rs:41-139`
51. 🔧 **[H·L]** ScopedEffect IR variant carrying AnimatableValue - The target Effect enum holds only scalars and a Whole|Range scope; to support keyframing the IR must carry AnimatableValue per param so the pure compiler emits expressions, otherwise the planned Timeline IR locks in scalar-only design. `architecture.md:374-387`
52. 💡 **[H·L]** Asset manager with search, filter, tags - The library is an unindexed flat list rewritten whole on every change (library.rs:80-97) with no search/filter/pagination, unusable past a few dozen items. `backend/src/library.rs:56-113; docs/audit.md:156`
53. 🐞 **[H·L]** Unify library.json and SQLite under one media table with FKs - library.json and projects/render_cache are independent stores (audit #28, #192) with no shared media id, so they drift and there is no FK to enforce that a project's source still exists. `backend/src/library.rs:56-63`
54. 🐞 **[H·L]** Project references media by id, not an embedded local path blob - Project.video stores the whole VideoInfo blob including the local /files url (db.rs:54-62, audit #105), so the project is tightly coupled to one machine's storage layout and breaks on any move. `backend/src/db.rs:50-62`
55. 💡 **[H·L]** Export a self-contained project bundle (recipe + used media) - There is no way to move a project to another machine; Project.video embeds a local /files path (db.rs:54-62) that is meaningless elsewhere, so a bundle (zip of source + edit JSON) is the only portable unit. `backend/src/db.rs:50-62`
56. 💡 **[H·L]** Import a project bundle and register its media - A bundle export is useless without a matching import that unpacks media into sources/, registers library entries, and recreates the project keyed to the new local id. `backend/src/handlers/projects.rs:14-44`
57. 💡 **[H·L]** Relink-by-hash workflow for offline source files - library.list() (library.rs:103-113) just hides entries whose file is gone with no way to point the project at a re-downloaded or moved copy, so 'all clips offline' is unrecoverable today. `backend/src/library.rs:99-113`
58. 🔧 **[M·S]** Persist source provenance type (url-import vs upload) per media - MediaEntry.kind only distinguishes source vs output; it cannot tell a re-downloadable URL import from an irreplaceable local upload, which changes the relink strategy entirely. `backend/src/library.rs:12-29`
59. 🔧 **[M·S]** Open output media back into the editor, not just sources - openFromLibrary refuses kind!=='source' (store.ts:345-346), so a rendered output cannot be re-edited or chained, forcing re-import of one's own export. `frontend/src/store.ts:345-368`
60. 🐞 **[M·S]** Reconstruct full VideoInfo when reopening from library - openFromLibrary defaults duration/width/height to 0 when the entry lacks them (store.ts:349-356), producing a broken editor state (zero-length trim, empty crop) instead of re-probing. `frontend/src/store.ts:345-368`
61. 🐞 **[M·S]** render_cache not invalidated when output file deleted (cache-hit 404) - Audit #25: cache_get is gated by a file-existence check now, but TTL cleanup deleting an output still leaves the cache row, so confirm cache_delete fires on file-miss and on every output removal path. `backend/src/handlers/mod.rs (cache_get ~275), backend/src/db.rs (cache_get/cache_delete)`
62. 🐞 **[M·S]** persist errors silently swallowed (job lost on restart) - Audit #31: set_job/persist_job ignore the persist Result, so a write failure leaves the job only in memory and it vanishes after restart with no signal. `backend/src/state.rs (set_job/persist_job ~60-65)`
63. 🐞 **[M·S]** No filesystem lock guarding storage against two backend processes - Audit #196: nothing prevents two backend instances from opening the same storage dir and SQLite file, which can corrupt the DB and race on file writes. `backend/src/main.rs (startup, no storage lock)`
64. 🐞 **[M·S]** Render cache key ignores ffmpeg/pipeline version - render_cache_key hashes only the serialized EditRequest (mod.rs:255-259); a ffmpeg upgrade or args-builder change returns a stale cached render for an identical request. `backend/src/handlers/mod.rs:252-259`
65. 💡 **[M·S]** Export/import presets as a JSON file - Presets live only in localStorage under ve_presets (store.ts:497) and vanish with the browser profile; a file round-trip lets users share and back up looks. `frontend/src/store.ts:458-535`
66. 🐞 **[M·S]** No deny_unknown_fields on any request DTO - EditRequest/ImportRequest/Trim/Crop/Scale silently drop unknown fields (model.rs:83-212), masking client/contract drift and typos as no-ops. `backend/src/model.rs:83-212`
67. 🐞 **[M·S]** Frontend applies presets/projects via unchecked as casts - applySnapshot and loadPresets coerce untrusted JSON with `as EditState` and Object.assign without filtering to PRESET_KEYS (store.ts:414-419,514-519), so a stale or foreign blob can clobber geometry. `frontend/src/store.ts:414-419,486-535`

## Редактирование и таймлайн (27)

68. ✅ 💡 **[H·M]** Split clip at playhead (razor) producing two segments - There is no way to slice a clip into independent parts at the current player time, the most basic NLE gesture, even though the concat backend already accepts N segments. `frontend/src/store.ts:311; backend/src/tools/args.rs:431` **[закрыто: панель «Таймлайн», клавиша S]**
69. 💡 **[H·M]** Multi-piece cut (remove several ranges, keep the rest) - The backend segments path supports arbitrary keep-ranges but the UI only lets the user remove a single middle range via a fixed cut slider. `frontend/src/components/EditPanel.vue:421; backend/src/tools/args.rs:524`
70. 💡 **[H·M]** Define Keyframe { time, value, interp } struct in IR - There is no keyframe data structure anywhere in the codebase; a time/value/interpolation triple per parameter is the atomic unit every other keyframing item builds on. `backend/src/model.rs`
71. 💡 **[H·M]** Interpolation modes: hold, linear, smooth (bezier) - Keyframes are useless without a sampling rule; hold/linear/ease-in-out cover the bulk of real edits and map directly to ffmpeg expression math (lerp / smoothstep). `backend/src/tools/args.rs`
72. ✅ 💡 **[H·M]** Ken Burns pan/zoom via keyframed zoompan - A keyframed start/end rect mapped to zoompan z/x/y expressions delivers the single most common animation users want on stills and talking heads, and the fragment is already noted as ready to land. `docs/ideas/round-13.md:42` **[закрыто: панель «Движение», zoompan по ключевым кадрам]**
73. 🟡 💡 **[H·M]** Animatable crop rectangle (animated reframe) - crop is a static x/y/w/h struct; keyframing the rectangle enables animated reframing/punch-in within a clip, a core capability for vertical-reframe and emphasis edits. `backend/src/model.rs:199-205` **[частично: анимируется зум/панорама/поворот и 360-перекадрирование; сам crop-прямоугольник по-прежнему статичен]**
74. ✅ 💡 **[H·M]** Keyframe diamond track in the timeline ruler - Users need add/move/delete keyframes at the playhead on a per-parameter lane; a diamond-marker track under the existing playerTime scrubber is the standard interaction and reuses the current time model. `frontend/src/components/VideoPreview.vue:8-21` **[закрыто: components/keyframe/KeyframeTrackEditor.vue]**
75. 🔧 **[H·M]** Add-keyframe-at-playhead button on each parameter control - To animate a slider, users must stamp its current value at the playhead (the stopwatch toggle pattern); without a per-control affordance the value-graph has no easy entry point. `frontend/src/components/EditPanel.vue`
