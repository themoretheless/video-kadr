# Локальное озвучивание текста

Для Pocket TTS доступно «Качество Pocket»: 3 шага («Быстро»), 5 («Обычное», по умолчанию), 8 («Тщательно»). Это число шагов генерации модели, а не гарантированная оценка качества звука. В запросах озвучки необязательное поле `numSteps` принимает только 3, 5 или 8 и только для Pocket; без поля используются 5 шагов. Выбор сохраняется вместе с заданием. При переключении на Kokoro или Chatterbox панель не передаёт этот параметр.

Для нативного Kokoro можно настроить три абсолютных пути: `KOKORO_NATIVE_BIN` к `video-kadr-sherpa-runtime`, `KOKORO_SHERPA_LIBRARY` к официальной библиотеке sherpa C API и `KOKORO_ORT_LIBRARY` к ONNX Runtime. Настройки задаются только вместе. Этот дополнительный движок собирается из `backend/sherpa-runtime` с официальной shared-библиотекой sherpa-onnx 1.13.8; автоматической установки пока нет. Дочерний процесс проверяет, что загружены именно указанные библиотеки. Текущая реализация проверки путей библиотек поддерживает Unix; остальные платформы отклоняются явно.

При таком подключении Kokoro панель показывает «Паузы между предложениями»: коэффициент 0–1, по умолчанию 0,2. Ноль отключает добавленную межфразовую паузу, но не удаляет естественные паузы внутри сгенерированной речи. API принимает необязательное `pauses` только для Kokoro с настроенным нативным движком; значение сохраняется в зашифрованном задании и используется после восстановления очереди. `GET /api/speech/voices` сообщает `supportsPauses`. Для прежнего sherpa CLI, Pocket и Chatterbox этот регулятор не показывается.

В панели локальной речи доступен раздел «Озвучить текст локально»: проверка голосов, текст, выбор голоса и скорости, прослушивание и скачивание WAV. Нужен настроенный на сервере движок; модель можно скачать в разделе «Модели озвучивания» либо задать на сервере. Без них интерфейс сообщает о недоступной модели; облачного или системного запасного голоса нет.

## Настройка сервера

- `SHERPA_TTS_BIN`: путь к официальному `sherpa-onnx-offline-tts` (по умолчанию ищется в PATH).
- `KOKORO_MODEL_DIR`: абсолютный путь к распакованному комплекту Kokoro v1.0. Ожидаются `model.int8.onnx` или `model.onnx`, `voices.bin`, `tokens.txt`, `lexicon-us-en.txt`, `lexicon-zh.txt` и каталог `espeak-ng-data`. Сохраните лицензии комплекта.
- `KOKORO_THREADS`: 1–16, по умолчанию 2. Текущий адаптер явно использует CPU.

Модели и команды: [официальная документация sherpa-onnx](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/kokoro.html). Проверены sherpa-onnx 1.13.8 для macOS arm64 и `kokoro-int8-multi-lang-v1_0`, snapshot `2a360693d79b88b49b88e29aec2b53577f41f206` из репозитория автора `csukuangfj/kokoro-int8-multi-lang-v1_0` на Hugging Face. SHA-256 сети: `4b86207ef680e394d8343bee22dfc4c512e5c707c6d9578e3f35ab09bffd6b36`.

Сборка приложения не загружает эти компоненты автоматически. В разделе «Модели озвучивания» откройте каталог, выберите компактный Kokoro либо Kokoro с полной точностью весов, скачайте и явно выберите его в списке моделей для новых озвучек. Скачивание сохраняется в истории аккаунта и продолжается после закрытия панели. Уже проверенные файлы используются при повторе; незавершённый отдельный файл скачивается с начала. Движок sherpa-onnx пока устанавливается отдельно. Каталог Whisper относится к распознаванию, а не к озвучиванию.

## API и ограничения

`GET /api/speech/voices` возвращает наличие выбранной модели, её голоса и ограничения:36английских/китайских для Kokoro v1.0 либо Bria, Loona и режим своего образца для Pocket. Наличие файла модели не является проверкой успешного запуска движка.

`POST /api/speech/synthesize` требует Bearer-сессию и JSON `{ "text": "Welcome to the project.", "voiceId": 3, "speed": 1.0 }`. Ответ — `audio/wav`, `Cache-Control: no-store`, фиксированное имя `narration.wav`. Заголовки `x-tts-sample-rate` и `x-tts-model-sha256` описывают результат и SHA-256 ONNX-сети. Пути файлов в запросе не принимаются.

Максимум текста — 4096 UTF-8 байт; скорость 0,5–2; синхронная генерация ограничена пятью минутами, фоновая — десятью минутами или меньшим общим лимитом сервера; файл — 64 МиБ/десять минут звука. Используется очередь Analysis. Для синхронного API временные файлы закрыты отдельным каталогом; файл публикуется без замены существующего, проверяется нативным WAV-парсером и удаляется после чтения HTTP-ответа. Фоновый API сохраняет отдельный приватный результат для истории. Ответ не размещается под публичным `/files/outputs`. Текст передаётся локальному CLI аргументом, поэтому не является секретом от других инструментов того же локального пользователя.

Проверены два английских голоса, изменение длительности при ускорении и распознавание синтезированного текста через настоящий Whisper. Качество всех голосов и китайской речи, другие платформы, ускорители, полная точность произношения и производительность не квалифицированы этими тестами.

Результат можно прослушать, скачать и кнопкой «Добавить озвучку на таймлайн» сохранить как медиафайл текущего нативного проекта. Сначала сохраните сам проект. Вставка в позицию курсора использует свободную аудиодорожку или создаёт новую и отменяется одним Undo; затем сохраните изменения проекта обычным способом. WAV хранится как оригинал, а не кеш, и не требует модели для последующего открытия проекта. Undo не удаляет сохранённый WAV из медиатеки.

Медиа получает доступ Space проекта. Для проекта без Space создаётся отдельный Space «Озвучка проекта» с его участниками; читатели могут слушать, добавлять файлы могут владельцы и редакторы. Изменения участников синхронизируются. Удаление проекта сохраняет оригиналы владельцу, отзывая у прочих участников доступ через служебный Space. Файлы находятся в защищённом каталоге Space, а не по публичному пути исходников.

`PUT /api/speech/narration-assets?projectId=…` принимает авторизованный WAV и возвращает обычную запись медиаисточника. Параметр projectId выбирается явно при добавлении; смена проекта во время сохранения не приводит к поздней вставке. Сохранённый файл остаётся в медиатеке исходного проекта. Проверены приватность, повторное открытие базы/медиатеки, сохранение документа, нативный аудиоэкспорт и браузерная вставка/Undo/Redo/сохранение/обновление страницы.

Ещё нужны установка/выбор моделей через интерфейс, полный пользовательский сценарий сетевой отмены, Pocket TTS и Chatterbox с клонированием голоса. Перенос приватной озвучки между независимыми проектами без Space пока требует отдельного решения; новые проекты не получают неявный доступ к чужим Space. Аварийная публикация/сборка оставшихся claims и весь экспорт/архив/платформенный корпус не квалифицированы. Полный перенос Concat, WeftCut и Filmcraft не завершён.

## Фоновые задания и история

Панель использует `POST /api/speech/tts-jobs`, затем наблюдает за заданием через `GET /api/jobs/:id`. Закрытие панели/страницы прекращает наблюдение и не отменяет генерацию. Кнопка отмены отдельно отправляет `POST /api/jobs/:id/cancel`. После потери соединения можно обновить состояние, не создавая вторую генерацию.

`GET /api/speech/tts-jobs` возвращает историю только текущего владельца: cursor/limit, по умолчанию 20, максимум 50. `GET /api/speech/tts-jobs/:id/audio` отдаёт ему проверенный по SHA-256 WAV без публичной ссылки. Готовый результат не требует установленной модели или движка. История не подставляет исходный текст в редактор. Полученный WAV по-прежнему можно добавить в выбранный сохранённый проект.

Запрос для незавершённой генерации хранится зашифрованным AES-256-GCM; контекст включает владельца, номер задания и отпечаток модели. Локальный ключ — файл `.tts-job-key` в STORAGE_DIR, в Unix права 0600. Сохраняйте этот файл вместе с резервной копией данных приложения. Если ключ недоступен, worker не создаёт новый; новые запросы также не заменяют пропавший ключ при наличии сохранённых зашифрованных запросов. После возврата прежнего ключа задание допускает повтор с тем же ID в рамках общей политики повторов. Долговременное восстановление при утрате ключа не поддерживается.

При штатной остановке сервера работающий дочерний процесс завершается, а задание сохраняется для старта приложения. Незаконченный расчёт запускается заново по прежнему запросу с прежним ID. Проверяются содержимое всего каталога модели и основной исполняемый файл; изменённые модель/запрос отклоняются. Каталог модели должен состоять из обычных файлов и каталогов без символических ссылок. Отпечаток не охватывает разделяемые библиотеки/ОС; аппаратные сбои и аварийная публикация отдельной проверки не прошли. Во время генерации показываются реальные состояния и неопределённый индикатор, а не выдуманный процент.

## Модели озвучивания

`GET /api/speech/tts-models` возвращает библиотеку владельца, выбранную модель и каталог Kokoro. `PUT /api/speech/tts-models/selection` принимает `{ "modelId": "…" }`; `configured` возвращает серверную настройку. Выбор сохраняется в SQLite и не меняет ранее принятые задания. Повреждённый выбранный комплект вызывает ошибку без подмены другой моделью.

`POST /api/speech/tts-model-downloads` принимает `{ "catalogId": "…" }` из каталога, а GET этого пути возвращает историю аккаунта с cursor/limit. Состояние, отмена и явный повтор используют обычные `/api/jobs/:id` маршруты с проверкой владельца. Только HTTPS-адреса закреплённой ревизии автора, размер и SHA-256 каждого из377файлов заданы приложением; пользовательские URL и пути не принимаются. Полностью проверенный каталог публикуется в `models/tts/{id}`, после чего модель добавляется владельцу без автоматического выбора. Промежуточный кеш находится в `tts-model-downloads/{jobId}`; закрытие интерфейса его не удаляет. Кнопка «Удалить выбранную модель озвучивания» скрывает модель из библиотеки аккаунта и сбрасывает выбор. Уже принятые задания и задания с сохранённым запросом для повтора удерживают комплект. Файлы освобождаются после удаления у последнего владельца и освобождения заданий; отложенная проверка выполняется при обновлении списка моделей. Серверная настройка, ссылающаяся на этот комплект, также сохраняет его. Повреждённый или неожиданный каталог автоматически не удаляется. Очистка незавершённых кешей и оставшихся после сбоя каталогов удаления через интерфейс пока не добавлена. Одновременная работа нескольких серверных процессов с одним хранилищем не квалифицирована.

`DELETE /api/speech/tts-models` принимает `{ "modelId": "…" }` и возвращает `{ "removed": true, "fileReleased": … }`. `fileReleased: false` означает, что запись владельца скрыта, а общий комплект пока сохранён. Удаление модели не удаляет готовые WAV и озвучку на таймлайне.

Скачивание, принятое до последнего удаления модели из аккаунта, не возвращает её в библиотеку: такой запрос завершается сообщением о необходимости нового скачивания. Чтобы установить модель после удаления, запустите новую загрузку из каталога. Номер поколения операции сохраняется в базе и в запросе задания; старые запросы без этого поля относятся к начальному поколению.

Для Kokoro в каталоге доступны два независимых комплекта: компактный int8 (189882497 байт) и полная точность весов (401239297 байт). Последний использует `model.onnx`, репозиторий автора [csukuangfj/kokoro-multi-lang-v1_0](https://huggingface.co/csukuangfj/kokoro-multi-lang-v1_0/tree/f7b96bb6bef5c5da4d3aa4f4e0498fbbf62dc78b), ревизию `f7b96bb6bef5c5da4d3aa4f4e0498fbbf62dc78b`, SHA-256 сети `b40f62b166ac8164b0627ef48a0b358eda0985e272fb03ef5252e7206305da11`. Выбор варианта не меняет список36английских/китайских голосов. Оба комплекта имеют собственные идентификаторы библиотеки, контрольные суммы, выбор и правила удаления; новая поддержка полной точности сама по себе не доказывает превосходство качества речи.

## Pocket TTS

В каталоге появился Pocket TTS с двумя штатными образцами Bria (voiceId1000) и Loona (1001), соответствующими Concat. Это отдельное семейство: голоса Kokoro для Pocket отвергаются и наоборот; список в панели обновляется при смене модели. Скачивание, выбор, приватная история, отмена, сохранение результата и удаление используют общий путь моделей/заданий. Загрузка пользовательского WAV-образца и voiceId1099 подключены. Выбор голоса непосредственно из клипа пока не подключён.

Комплект автора [csukuangfj2/sherpa-onnx-pocket-tts-int8-2026-01-26](https://huggingface.co/csukuangfj2/sherpa-onnx-pocket-tts-int8-2026-01-26/tree/e715955cf50d18d919d37231513c0e914b83661a), ревизия `e715955cf50d18d919d37231513c0e914b83661a`,12файлов/203216103байт. Идентификатор `f85f04c7acf76154571a1e6b398534c257574cece490d2bb7991eae5e8426d54`. Пять сетей ONNX и две таблицы проверяются общим каталогом; `x-tts-model-sha256` обозначает основную сеть `lm_main.int8.onnx` (`bfc0c7e7e3d72864fa3bb2ee499f62f21ddc1474b885f5f3ca570f8be73e787e`), а durable bundleHash включает весь комплект и исполняемый файл.

Используется официальный CLI sherpa-onnx1.13.8 наCPU,5шагов генерации; кеш эмбеддингов отключён для отдельных процессов. Штатный WAV-образец преобразуется собственным ограниченным WAV-путём в моно24кГц PCM16: максимум10секунд, минимум0,5секунды, до8МиБ исходного WAV,1–2канала/8–48кГц. Подготовленный образец хранится только во временном приватном каталоге вызова. Загрузка пользовательских путей или URL в API не разрешена.

Проверены настоящие Bria/Loona, сокращение длительности при скорости2 и распознавание сгенерированной английской фразы настоящим Whisper. Эти проверки не являются измерением сходства голоса, гарантией произношения всего корпуса, проверкой всех языков/платформ или переносом полного клонирования Concat.

## Свой WAV-образец

Выберите Pocket и голос «Мой образец голоса», укажите WAV и нажмите «Загрузить образец голоса». После подтверждения можно создать озвучку. Сервер использует первые10секунд (минимум0,5секунды), поддерживает1–2канала/8–48кГц и до8МиБ исходного файла; нормализованный образец — моно24кГц PCM16. Исходный файл/имя не сохраняются, нормализованный образец сохраняется приватно для фоновых заданий.

`POST /api/speech/tts-references` принимает WAV с Bearer-сессией и возвращает201 `{ "id": "uuid", "durationUs": …, "sampleRate": 24000 }`. Файлы лежат под `tts-references/{uuid}.wav` с0600в каталоге0700и не публикуются через `/files`; маршрута скачивания образца нет. При генерации передайте `voiceId:1099` и `referenceId:id`. Штатные голоса отвергают referenceId, а голос по образцу требует его. Чужой/неизвестный образец недоступен.

Новые durable TTS-задания schema2 шифруют текст и снимок `{id,hash,bytes}` образца вместе; schema1 с прежним плоским запросом остаётся читаемым. Перед генерацией и перед принятием результата сервер проверяет владельца, размер и SHA-256 снимка. Изменённый/недоступный образец останавливает задание без подмены штатным голосом. Готовый WAV затем доступен независимо от модели и образца; история восстанавливает наблюдение без повторной загрузки.

Список/удаление сохранённых образцов и очистка неиспользуемых записей пока не добавлены. Смена файла/аккаунта в панели очищает только локальный выбор и прекращает наблюдение за загрузкой; принятые сервером образцы сохраняются для заданий. Поддержка исходного клипа и форматов кроме WAV остаётся открытой.

### Saved private voice samples

For Pocket's custom voice, open **«Сохранённые образцы голоса»**, refresh and select a sample. Samples are private to the signed-in owner; clip-derived samples also require continued access to their original source. The list supports **«Ещё образцы голоса»**. Unavailable source samples cannot be selected for synthesis.

**«Убрать образец из библиотеки»** hides the sample and prevents its use in new requests. Already admitted narration jobs retain their captured reference, including after managed restart; source-access revocation still applies. Removed samples are reclaimed on removal or the next owner library refresh once no retained narration request needs them. Files are checked against their recorded size and SHA before deletion. Corrupt requests or unavailable keys conservatively retain samples; changed or symbolic-link files are not deleted automatically.

API: authenticated `GET /api/speech/tts-references?limit=20&cursor=<UUID>` returns `references` and `nextCursor`; authenticated `DELETE /api/speech/tts-references` accepts `{ "referenceId": "<UUID>" }`. Removal is idempotent for the owner; `filesRetained` reports whether a private sample file remains. Retained retryable requests keep their sample until completion or request discard.

### Chatterbox Turbo runtime configuration

The managed catalog includes the pinned q8 Chatterbox Turbo bundle. Configure both
`CHATTERBOX_TTS_BIN` (absolute path to the built `video-kadr-chatterbox` Rust CLI)
and `CHATTERBOX_ORT_LIBRARY` (absolute path to its compatible ONNX Runtime library).
No automatic runtime installation is performed. Neither path is accepted from HTTP.

After installing and explicitly selecting Chatterbox, custom voice2099 uses the
same private saved/uploaded/source-clip references. A5..10second reference is
required; shorter Pocket-compatible samples remain saved but cannot start a
Chatterbox request. The model controls its own pace, so speed is fixed at1.
Captured jobs resolve their admitted model ID and runtime fingerprint independently
of subsequent owner selection changes. Stock Chatterbox Bria2000 is not offered yet.
