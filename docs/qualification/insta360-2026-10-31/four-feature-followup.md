# Neural recovery, optical flow, sensor rows and drift

This stage supersedes the previous follow-up's statements that these four capabilities are absent. It implements independent native algorithms; it does not establish full DeepTrack/FlowState quality parity.

## Available behavior

- **Neural identity recovery:** the saved SAM object seeds immutable neural identity and appearance. Global proposals can recover it after arbitrarily long gaps within the bounded sampled interval; occluded or ambiguous samples produce no measurements. Raw dual-lens sources are prepared through calibrated native stitching before inference, then measurements are mapped through the current gyro camera transform. See [identity report](reidentification/README.md). The existing local SAM executable, models and ONNX Runtime must be provisioned; the runtime now advertises schema14. No vendor weights are used.
- **Optical-flow stitching:** choose Optical flow in the dual-fisheye inspector. The Rust sampler estimates subpixel correspondence, checks reverse consistency, rejects ambiguous/occluded regions and applies symmetric seam warps. Calibrated feathering remains the fallback. Preview and export share the implementation. See [flow qualification](optical-flow-followup.md).
- **Rolling shutter:** enable correction in embedded gyro import. Metadata readout time is interpreted in milliseconds, with an explicit manual override and per-lens scan direction. Rays use their projected physical sensor row, actual capture-clock inversion and row-specific gyro orientation. A bounded implicit row solve handles projection dependence; the same corrected sampler feeds flow and semantic seed projection. Ready-stitched panorama input is rejected because physical source rows are unavailable. Translational/depth rolling shutter remains outside this rotational model.
- **Drift correction:** import can use explicit sensor bias, explicitly stationary intervals, measured heading anchors or opt-in static-background video observations. Gravity alone does not observe yaw; slow camera pans are not treated as stationary. Unobservable/ambiguous background measurements return warnings instead of invented zero drift. See [drift implementation and evidence](drift-followup.md).

## Time and render integration

Precise import preserves native gyro motion rather than uniformly reducing it to60Hz. Adaptive quaternion compression retains the requested0.005-degree error at supplied knots with a hard20000-key limit; it fails explicitly if the bound cannot fit. This is not a continuous physical-motion certificate. Exposure/shutter breakpoints are retained on the exact piecewise-linear capture clock, then compressed to a1ns physical-time error bound. When rolling shutter is enabled, the importer reads real pre/post gyro guard bands and returns a0.1-second orientation offset. Ordinary import uses no mandatory guard band, so footage without extra sensor samples remains importable. Beyond actual video endpoints only the clock gauge is extended; physical gyro samples remain required and the report warns about the extension.

Saved documents receive a separately bounded16MiB aggregate allowance only for validated spherical motion/capture-clock arrays. Unrelated metadata retains the ordinary2MiB allowance.

A proven rational source-frame clock selects the orientation of the actual decoded/held source frame, independently of output FPS. The desired virtual camera path remains evaluated at output time. Without a proven ordinary constant-rate clock, rolling-shutter UI import refuses to apply the correction. Unproved timing, arbitrary PTS, retiming and other camera variants remain separately scoped.
