# Аудит: топ-500 «сделано плохо или неправильно»

509 различимых проблем, заземлённых на код (`file:line`). Собрано мульти-агентным проходом (28 линз: поф айловый разбор + сквозные концерны) в несколько заходов из-за временного rate-limit API, затем объединено и дедуплицировано (лексически + по `file:line`). 917 сырых находок -> 509 уникальных.

Состав по серьёзности: 🔴 high - 34, 🟠 medium - 128, 🟡 low - 347.

**Важно про доверие к списку.** Поштучной adversarial-верификации (как в [docs/audit.md](audit.md)) тут НЕ было - это широкий охват, не глубокая проверка. Высокоуверенное ядро (118 проверенных проблем, 14 опровергнутых) остаётся в [docs/audit.md](audit.md). Здесь каждая находка заземлена на прочитанный код, но среди 🟡-хвоста (347 шт.) ожидаемы дубли-перефразировки и спорные ниты: токенный дедуп не ловит все смысловые повторы (особенно SSRF/auth, описанные разными словами). ## Безопасность (31)

1. 🔴 Backend bound to 0.0.0.0 in Docker with no auth/firewall - The image sets BIND_ADDR=0.0.0.0 so the backend listens on all interfaces; combined with no authentication (the whole API, incl. SSRF-driving /api/import and ServeDir at /files) this means any host that can reach the container port has full access. The compose backend has no published ports, but the Dockerfile alone (run directly) exposes everything. → Default to 127.0.0.1 inside the image and only widen the bind when fronted by an authenticated proxy; document the requirement prominently. `backend/Dockerfile:16-17`
2. 🔴 No auth/ownership: any client can read any project - project_list_handler and project_get_handler have no auth or ownership check, so any client enumerates all saved projects and their full video metadata (URLs, filenames) across all users of the instance. → Introduce a session/owner key and scope project queries to the owner, or document and enforce single-tenant-only deployment. `backend/src/handlers/projects.rs:47-80`
3. 🔴 No auth on project deletion (any id deletable) - project_delete_handler deletes by raw id with no ownership check; any client that can reach the API can delete any other client's saved project, causing data loss. → Gate deletion behind ownership/auth, or restrict the endpoint to trusted callers. `backend/src/handlers/projects.rs:83-92`
4. 🔴 ServeDir exposes SQLite WAL/SHM sidecar files - Db::open uses SqliteJournalMode::Wal (db.rs:75), so app.db-wal and app.db-shm sit next to app.db in storage/ and are downloadable at /files/app.db-wal; the WAL holds committed-but-not-checkpointed rows, so even excluding app.db itself the full DB contents leak. Audit #35 names only app.db/library.json, not the WAL sidecars. → Move the SQLite database (and its -wal/-shm) out of the directory served by ServeDir, e.g. open it under storage/db/ while serving only storage/sources and storage/outputs, or nest two ServeDir mounts scoped to sources/outputs. `backend/src/lib.rs:54`
5. 🔴 Permissive CORS lets any site read API response bodies - CorsLayer::permissive() sends Access-Control-Allow-Origin reflecting any origin, so a browser on any malicious page can issue GET /api/library and GET /api/projects and read the JSON response (video titles, source URLs, project names) cross-origin: a read information-disclosure path distinct from audit #36, which only flags mutating POST/DELETE. → Replace permissive() with an explicit allowlist of trusted origins (or same-origin only) for both safe and unsafe methods, and gate behind config per environment. `backend/src/lib.rs:56`
6. 🔴 yt-dlp can follow redirects to blocked targets - The URL is validated once up front, but yt-dlp follows HTTP redirects, so a public URL that 302-redirects to http://169.254.169.254/ or a private host bypasses the SSRF guard entirely. → Pass yt-dlp options to constrain/forbid cross-host redirects, or validate the final resolved target; at minimum document the limitation and consider an egress allowlist. `backend/src/tools/mod.rs:63-115`
7. 🔴 SSRF guard validates literal IPs only, never resolves DNS - validate_url only blocks when host_str() parses as an IpAddr; a hostname like internal.example resolving to 10.0.0.5 (or DNS-rebinding to 169.254.169.254) passes the guard and yt-dlp then fetches the private target. → Resolve the host (e.g. tokio::net::lookup_host) and run is_blocked_ip over every resolved A/AAAA address, rejecting if any is private; ideally pin/validate again at connect time. `backend/src/tools/net.rs:21-26`
8. 🔴 Decimal/octal/hex IP forms bypass is_blocked_ip - host_str() for http://2130706433/ returns "2130706433", which fails "2130706433".parse::<IpAddr>(), so is_blocked_ip never runs, yet curl/yt-dlp interpret it as 127.0.0.1 (same for 0x7f.1, octal 0177.0.0.1). → Normalize the host to canonical form before checking, or reject any all-numeric / non-dotted host that downstream tools would treat as an integer IP. `backend/src/tools/net.rs:21-25`
9. 🔴 No redirect policy after URL validation - Even if the initial URL is public, yt-dlp follows HTTP redirects unchecked, so a public URL can 302 to http://169.254.169.254/ or a private host, defeating the up-front validate_url. → Constrain yt-dlp redirects (e.g. limit/forbid cross-host redirects) or re-validate the final resolved host; document that validate_url alone is insufficient. `backend/src/tools/net.rs:10-27`
10. 🟠 No filename validation when reconstructing cached output path - cache_get returns a filename later joined onto outputs_dir for metadata; a poisoned/legacy cache row with '../' could traverse, and the value is trusted without sanitization. → Validate the cached filename is a plain basename (no separators / '..') before join, or store and reuse only the canonical out_id-based name. `backend/src/handlers/mod.rs:275-278`
11. 🟠 No authentication on any endpoint, ServeDir exposes app.db - All routes are unauthenticated and nest_service('/files', ServeDir::new(storage)) serves the entire storage dir including app.db and library.json, so exposing the port leaks the database and all media (README warns, but Dockerfile binds 0.0.0.0). → Add auth middleware before exposure, move app.db/library.json outside the served storage root, and restrict ServeDir to media subdirs. `backend/src/lib.rs:28-58`
12. 🟠 No authentication on destructive/expensive endpoints - All routes including DELETE library/projects and the resource-heavy import/edit are unauthenticated, so anything that can reach the port can delete data or launch heavy ffmpeg/yt-dlp jobs. → Add a token/shared-secret middleware or bind strictly to loopback and document the trust boundary; gate destructive routes at minimum. `backend/src/lib.rs:30-57`
13. 🟠 file_path() trusts filename for path joins (traversal risk) - file_path joins e.filename directly under storage/<sub>; if a filename containing path separators or '..' ever reaches a MediaEntry (e.g. via from_result from a crafted result blob), remove() could delete and list() could stat files outside the intended directory. → Validate/normalize filename to a single path component (reject separators and '..') in from_result, and assert the canonicalized file_path stays within storage before any fs operation. `backend/src/library.rs:138-145`
14. 🟠 Raw ffmpeg/yt-dlp stderr leaked to client error - map_ytdlp_error's fallback and run_ffmpeg's failure embed raw tail(stderr) (which can contain absolute filesystem paths and internal URLs) into job.error, shown directly to the user. → Return a generic user-facing message and log the raw stderr at debug/error level only. `backend/src/tools/mod.rs:113, 144, 288`
15. 🟠 SSRF guard only checks literal IPs, not resolved DNS - validate_url blocks localhost/private literal IPs but a hostname resolving to 127.0.0.1/169.254.169.254 (or a redirect there) passes, and yt-dlp then connects, so the SSRF guard is bypassable via DNS or redirect when the service is exposed. → Resolve the host and reject if any A/AAAA is private/loopback/link-local; disallow redirects to private targets in yt-dlp. `backend/src/tools/net.rs:10-27`
16. 🟠 CGNAT range 100.64.0.0/10 not blocked - Ipv4Addr::is_private() does not include carrier-grade NAT space (100.64.0.0/10), so an attacker on such a network can target gateway/management hosts in that range. → Add an explicit check: octets[0]==100 && (64..=127).contains(&octets[1]). `backend/src/tools/net.rs:31-37`
17. 🟠 Link-local IPv6 mask uses wrong bit width - fe80::/10 should mask the top 10 bits (0xffc0 & 0xfe80==0xfe80) but the comparison `(seg[0] & 0xffc0) == 0xfe80` only matches fe80..febf; fec0::/10-style site-local and the rest of fe80::/10's intent are fine, but unique-local check `(seg[0] & 0xfe00) == 0xfc00` correctly covers fc00::/7 - the real gap is no coverage of deprecated site-local fec0::/10. → Keep fe80::/10 as-is but add fec0::/10 (deprecated site-local) and IPv4-mapped handling; double-check masks with unit tests for boundary addresses. `backend/src/tools/net.rs:44`
18. 🟠 Frontend nginx /files proxy has no auth, mirrors backend exposure - nginx proxies /files/ straight to backend:8080 with no auth, so the SQLite/library/temp exposure of ServeDir (lib.rs:54) is reachable through the public frontend on port 8088, not just internally; this is the deployment surface that turns the ServeDir issue into a real exposure. → Scope the proxied path to /files/sources/ and /files/outputs/ only (or fix the backend to serve only those subtrees) and add auth at the proxy. `frontend/nginx.conf:24-28`
19. 🟡 ServeDir + CORS leak health tool versions cross-origin - /api/health returns exact ffmpeg/yt-dlp version strings and, under CorsLayer::permissive(), any web page can fetch and read them cross-origin, fingerprinting the install for known-CVE targeting; the endpoint has no auth or origin gate. → Restrict version detail to authenticated/internal callers, or split a public liveness probe (status only) from a detailed readiness endpoint behind the origin allowlist. `backend/src/handlers/health.rs:10-18`
20. 🟡 Upload trusts file without magic-byte/type validation - The handler keeps any extension via sanitize_ext and only relies on ffprobe succeeding; a crafted file that ffprobe accepts but mislabels could be served under /files with an attacker-chosen extension. → Sniff container/magic bytes and constrain the stored extension to a server-derived value from the probed codec/container. `backend/src/handlers/mod.rs:151-200`
21. 🟡 edit_handler logs full ffmpeg command line at info - tracing::info!("ffmpeg {}", args.join(" ")) logs absolute input/output paths (and any filter contents) at info level on every render, leaking filesystem layout into logs that may be shipped. → Lower this to debug level, or log only the output filename and a summary of the edit rather than the full path-bearing command line. `backend/src/handlers/mod.rs:333`
22. 🟡 Job ID enumeration exposes other users' results - GET /api/jobs/:id returns any job's status/result by id with no ownership check; combined with no auth, knowing/guessing a UUID returns its output URL and error details. → Once auth exists, scope job lookups to the authenticated owner; otherwise document the single-user trust model explicitly. `backend/src/handlers/mod.rs:370-378`
23. 🟡 CorsLayer::permissive on mutating POST/DELETE routes - CorsLayer::permissive() allows any origin to call edit/import/delete/projects, so any website the user visits can drive the local backend (CSRF-like) when it is running. → Restrict CORS to the known frontend origin and limit methods, or gate behind same-origin. `backend/src/lib.rs:55-57`
24. 🟡 TraceLayer logs full request URIs including import URLs - TraceLayer::new_for_http() with default config logs request path/headers; import URLs arrive in the JSON body (not path) so those are safe, but query strings on any future GET and the X-Forwarded-For added by nginx are logged with no redaction policy, and there is no documented RUST_LOG/redaction story for this layer. → Configure TraceLayer with an explicit MakeSpan that omits sensitive fields and document the logging/redaction policy. `backend/src/lib.rs:55`
25. 🟡 ServeDir clones storage path but no symlink policy set - ServeDir::new(&storage) uses default symlink behaviour; if an uploaded/derived file or a symlink ever lands in storage/sources, ServeDir may follow it outside the intended tree, and the code never calls a symlink-restricting option to make intent explicit. → Explicitly configure the ServeDir symlink behaviour (or document that storage is trusted) so the policy is intentional rather than defaulted. `backend/src/lib.rs:29,54`
26. 🟡 Raw ffmpeg/yt-dlp stderr (with paths) returned in job.error - map_ytdlp_error falls through to 'yt-dlp: {tail}' and run_ffmpeg returns 'ffmpeg failed: {tail}', leaking absolute storage paths and internal details into job.error shown to the user via the frontend. → Log raw stderr at debug and return a generic user-safe message; never include filesystem paths in job.error. `backend/src/tools/mod.rs:144-145, 288`
27. 🟡 map_ytdlp_error can leak raw stderr to client - The fallback branch returns format!("yt-dlp: {}", tail(stderr,6)) directly to the API/job error, potentially exposing local paths, tokens in URLs, or internal details to the frontend. → Return a generic message to the client and log the raw stderr server-side only, or scrub paths/URLs from the tail before surfacing it. `backend/src/tools/mod.rs:131-146`
28. 🟡 ffmpeg/yt-dlp resolved via PATH, not absolute - Commands are spawned by bare name ("ffmpeg", "yt-dlp", "ffprobe"), so a poisoned PATH or a shadowing binary in the working directory could be executed instead of the intended tool. → Resolve the tool paths once at startup (or via env like FFMPEG_BIN) to absolute paths and spawn those, validating they exist. `backend/src/tools/mod.rs:49, 83, 190, 265`
29. 🟡 IPv4-mapped IPv6 and CGNAT not blocked - is_blocked_ip misses ::ffff:127.0.0.1 (IPv4-mapped loopback) and 100.64.0.0/10 (CGNAT), so those addresses pass the literal-IP check. → Unmap IPv4-mapped IPv6 before classifying, and add the 100.64/10 range to the blocklist. `backend/src/tools/net.rs:29-47`
30. 🟡 validate_url does not block 169.254.169.254 metadata explicitly - 169.254.0.0/16 is covered by is_link_local for a literal IP, but other reserved ranges (100.64.0.0/10 CGNAT, 192.0.0.0/24, IPv4-mapped IPv6 ::ffff:127.0.0.1) are not blocked, leaving metadata/SSRF gaps. → Also reject CGNAT and IPv4-mapped IPv6 ranges (unwrap v6 to v4 via to_ipv4_mapped and re-check) so mapped/loopback addresses cannot slip through. `backend/src/tools/net.rs:29-47`
31. 🟡 validate_url does not reject userinfo/credentials in URL - A URL like http://localhost@evil.com or http://evil.com@127.0.0.1 parses with host_str() returning the real host, but embedded credentials can confuse downstream tooling and aid SSRF bypasses. → Reject URLs containing username/password components, or strip them explicitly before validation and download. `backend/src/tools/net.rs:10-20`

## Корректность и гонки (79)

32. 🔴 cancel_handler vs finish_job terminal-state race - cancel_handler sets Cancelled under one lock acquisition while the worker's finish_job updates under a separate one; finish_job uses update_job_if_open (guards terminal) so a Done can't overwrite Cancelled, but the cancel token may be cleared by finish_job before cancel() runs, leaving a brief window where cancel() finds no token and the user sees success while the render already completed. → Make the cancel decision atomic with the status read (check is_terminal and signal under the same jobs lock) and treat 'no live token' as already-finished. `backend/src/handlers/mod.rs:381-408, 552-590`
33. 🔴 Concurrent identical edits orphan output files - Two simultaneous identical requests both miss cache_get, each render to a distinct out_id file, and both cache_put the same key last-writer-wins, leaving the loser's output file on disk with no cache row and no library entry (resource leak). → Serialize per-cache_key work (e.g. an in-flight map of cache_key -> shared JoinHandle/Notify) so the second request awaits the first's result instead of rendering, or delete the prior cached filename inside cache_put when it differs. `backend/src/handlers/mod.rs:268-359`
34. 🔴 Speed >2.0 desyncs audio: video setpts unclamped, atempo clamped - video_filters uses raw edit.speed in setpts while audio_filters clamps atempo to [0.5,2.0], so a speed outside that range (no server-side speed clamp in normalize_edit_geometry) sets video to Nx but audio to at most 2x, producing permanent A/V desync. → Clamp speed once in normalize_edit_geometry (or apply chained atempo factors to cover the full range) so video and audio use the same effective speed. `backend/src/tools/args.rs:139-141, 169-173`
35. 🔴 setpts honors any speed but atempo is clamped, desyncing A/V - Video setpts uses 1/speed for any speed>0 while audio atempo is clamp(0.5,2.0); a request with speed=3 (the API accepts it; only the frontend preset list stops at 2) yields 3x video over 2x audio, silently desyncing the result. → Clamp `speed` to [0.5,2.0] in normalize_edit_geometry (server-side), or emit a chained atempo (e.g. atempo=2,atempo=1.5 for 3x) so audio matches the video rate. `backend/src/tools/args.rs:138-142, 169-173`
36. 🔴 Autosave watch fires on video change before restore - openFromLibrary sets state.video and a default edit (synchronous), which triggers the deep autosave watch and schedules persistProject in 1000ms; restoreProject is async (a network round-trip) and may resolve after that timer, so the just-loaded defaults can be POSTed over a previously saved edit before (or even after) the real edit is restored. → Suppress autosave until restore completes: set a 'restoring' flag in openFromLibrary, clear it at the end of restoreProject, and have the watch return early while it is set (and clear any pending projectSaveTimer when switching clips). `frontend/src/store.ts:345-368, 598-609`
37. 🔴 openFromLibrary races default-edit autosave against restore - openFromLibrary synchronously sets state.video and a DEFAULT state.edit (arming the 1000ms autosave timer), then fires restoreProject async; if getProjectByVideo takes >1s (cold backend) persistProject runs first and overwrites the saved project with the default recipe, destroying the user's stored edit before it is ever read. → Cancel/suspend the autosave timer until restoreProject resolves (await it before any save can fire), or guard persistProject with a per-video 'restored' flag so it never writes a clip whose restore has not completed. `frontend/src/store.ts:357-367, 569-596`
38. 🟠 upsert_project SELECT-then-INSERT is not transactional (race) - Two concurrent autosave requests for the same video_id can both see existing=None and both INSERT, producing duplicate project rows (video_id has no UNIQUE constraint, only an index), after which get_project_by_video silently returns whichever LIMIT 1 wins and the other row is orphaned. → Add a UNIQUE constraint on projects.video_id and use a single INSERT ... ON CONFLICT(video_id) DO UPDATE, or wrap the read+write in a transaction with the pool's connection. `backend/src/db.rs:96-131`
39. 🟠 row_to_job maps unknown/corrupt status to Pending (non-terminal zombie) - from_token falls back to Pending for any unrecognized status string; recover_jobs flips non-terminal to Interrupted only at load, but a row written later with a corrupt status (or a future status token) loaded outside recovery is treated as Pending, a non-terminal state with no live task or cancel token, so a polling client spins forever. → Make from_token return a dedicated Unknown/Interrupted variant (or have row_to_job reject unknown tokens) so corrupted statuses resolve to a terminal state, never resurrect as Pending. `backend/src/db.rs:291; model.rs:38-47`
40. 🟠 Cancellation race overwrites status with Running in import worker - After the cancel check at line 73, an unconditional update_job sets status=Running; a cancel arriving between the check and the write is silently clobbered, so the job runs anyway. → Use update_job_if_open for the Running/downloading transition (as the edit path's terminal transitions do) so a concurrent Cancelled state is not overwritten. `backend/src/handlers/mod.rs:73-83`
41. 🟠 Edit worker also overwrites cancelled status with Running - Same pattern as import: the cancel check at 305 then an unconditional update_job at 310 can clobber a cancellation that lands in between, so ffmpeg still runs. → Set the Running transition via update_job_if_open and bail out (releasing the permit) when it returns false. `backend/src/handlers/mod.rs:305-315`
42. 🟠 Concurrent add()/remove() can lose writes (last-writer-wins) - Both add() and remove() snapshot under the lock, drop the lock, then save() outside it; two concurrent operations can interleave their saves so the second save() writes a stale snapshot, silently undoing the first operation on disk. → Hold the lock across the save (or serialize saves via a dedicated writer task / additional save mutex) so the persisted file always reflects the last committed in-memory state. `backend/src/library.rs:90-97,125-136`
43. 🟠 render_cache not invalidated when output deleted by TTL - cache_delete_filename is only called on explicit library delete (library.rs handler); TTL cleanup deletes output files directly without calling it, so a later identical edit gets a cache hit, then the metadata check at edit_handler:276 fails and only then evicts, adding latency and a confusing first-attempt path. → Call db.cache_delete_filename for each output file the TTL job removes. `backend/src/main.rs:103-135`
44. 🟠 TTL cleanup deletes files but leaves DB/library rows - spawn_cleanup removes files older than TTL directly from disk but never updates library.json or render_cache, so the library hides them on list() yet entries linger and stale cache rows point at deleted files until a separate request evicts them. → Route TTL deletion through Library::remove and db.cache_delete_filename so all three (file, library, cache) stay consistent. `backend/src/main.rs:102-135`
45. 🟠 Segments not sorted by start time - valid_segments preserves request order and build_concat_args emits trim/concat in that order, so out-of-order segments (e.g. [{3,4},{0,1}]) stitch the timeline backwards instead of chronologically. → Sort the collected segments by start (and ideally by start then end) in valid_segments before building the concat graph. `backend/src/tools/args.rs:444-455, 524-529`
46. 🟠 Single atempo stage cannot reach speeds beyond 2x/below 0.5x - atempo only accepts 0.5..=2.0 per stage; for speeds outside that range a single atempo silently clamps rather than chaining stages, so audio tempo is wrong whenever speed leaves the band. → Build a chain of atempo factors whose product equals `speed` (split into 2.0 / 0.5 steps) instead of a single clamped atempo. `backend/src/tools/args.rs:170-173`
47. 🟠 pad aspect computed on scaled dims, not source - `pad` is pushed after `scale`, so when both are present the iw/ih in the pad expression are the scaled dimensions; combined with crop's `& !1` even-rounding the centered frame can shift by a pixel and the target aspect is taken against the resized frame rather than the user's intended source frame. → Decide and document a deterministic order (e.g. pad before scale, or compute pad against explicit target dims) and add a graph-level test asserting final WxH for crop+scale+pad together. `backend/src/tools/args.rs:96-104`
48. 🟠 Concat per-segment streams not labeled audio when one segment muted-by-trim - build_concat_args always emits `[0:a]atrim...` for every segment when not muted, assuming the input has an audio stream; if the source has no audio track, concat=n:a=1 references missing `[a{i}]` and ffmpeg fails the whole job. → Probe for an audio stream and set a=0 (or inject anullsrc) when absent, rather than unconditionally building audio segments from `[0:a]`. `backend/src/tools/args.rs:443-466`
49. 🟠 Concat path applies setpts twice causing wrong speed math - build_concat_args trims each segment with setpts=PTS-STARTPTS, then video_filters(temporal=true) appends another setpts={1/speed}*PTS on the concatenated stream; for speed!=1 this is correct only by luck, but fade_out timing uses out_dur derived from summed segment lengths / speed and can mismatch the actual concatenated+retimed duration. → Verify and add a test for a multi-segment edit with speed!=1 and fade_out; compute fade start from the true post-concat post-speed duration. `backend/src/tools/args.rs:444-475, 138-142`
50. 🟠 find_by_id can match a `<id>.mp4.part` partial download - find_by_id matches stem==id; a yt-dlp in-progress file `<id>.part` has stem `<id>` and would be returned by find_source if a concurrent edit/probe races the still-running download, yielding a truncated/corrupt input. → Skip entries whose extension is `part`/`ytdl`/`temp` (or whose name contains `.part`) in find_by_id, and/or only call find_source after Done::Completed (already done in import, but edit path at line 328 has no such guarantee against a stale partial). `backend/src/tools/mod.rs:171-186`
51. 🟠 Cancelled/timed-out child waited on without a timeout - After start_kill on cancel/timeout, child.wait().await blocks indefinitely; if the killed process is stuck in uninterruptible state the worker task hangs and never frees its semaphore permit. → Wrap the post-kill child.wait() in a tokio::time::timeout and log/proceed if it elapses, so a stuck child cannot pin a queue slot forever. `backend/src/tools/mod.rs:346-349`
52. 🟠 Timeout/cancel may leak child if streams stay open - The select loop only reaches child.wait() once both stdout and stderr hit EOF; on timeout it breaks first and kills, but if a child wedges with pipes open the post-kill child.wait().await has no timeout and can hang the worker indefinitely. → Wrap the post-kill wait in a bounded timeout and force-reap, ensuring the worker task always completes. `backend/src/tools/mod.rs:314-351`
53. 🟠 redo after pending change pushes wrong snapshot to past - Because redo() skips the flush, history.future was last populated by a stale lastSnapshot; redo pushes the CURRENT (mid-edit) snapshot to past while restoring an older future entry, so a subsequent undo returns to a state the user never saw, corrupting the linear history. → Flush the pending change before reading history.future (same fix as the redo flush), guaranteeing past/future always reflect committed snapshots only. `frontend/src/store.ts:433-437`

489. 🟠 EditRequest triple-role coupling: wire + cache key + ffmpeg - The same struct is the HTTP body, the canonical render-cache key source, and the ffmpeg arg input, so any added field or serde rename silently changes cache keys and can collide or miss without notice. → Separate the wire DTO from a validated/normalized internal edit model used for both cache-key hashing and arg building, with a version tag baked into the key. `backend/src/model.rs:92-181`
490. 🟠 yt-dlp invoked without sandboxing or rate limits - yt-dlp runs with full network/filesystem access of the server user and no size cap on the downloaded file, so a malicious URL can pull huge files (only resolution is capped, not bytes) or exercise yt-dlp extractor vulnerabilities. → Add --max-filesize, --no-exec, run under a restricted user/namespace, and cap concurrent imports; consider --downloader-args/network sandboxing. `backend/src/tools/mod.rs:83-103`
491. 🟡 load_jobs is dead production code (only tests use it) - Production recovery uses load_recent_jobs; load_jobs (unbounded SELECT of all jobs) is referenced only by the test at line 375, so it is effectively dead code that also re-introduces the unbounded-load footgun if a future caller picks it. → Remove load_jobs or mark it #[cfg(test)], routing the test through load_recent_jobs with a high limit. `backend/src/db.rs:207-215`
492. 🟡 WAL mode without checkpoint/size management - SQLite is opened in WAL mode with a 5-connection pool but no wal_autocheckpoint tuning or periodic checkpoint, so on a long-running busy install the -wal file can grow large before an implicit checkpoint. → Set a sensible wal_autocheckpoint / periodic PRAGMA wal_checkpoint(TRUNCATE), or document the expected growth. `backend/src/db.rs:71-83`
493. 🟡 yt-dlp downloaded title used as filename stem only, no sanitize of merged ext - find_source returns whatever file yt-dlp produced and its extension is embedded into the public /files URL and library; an unexpected container (yt-dlp not always honoring --merge-output-format) yields a filename the frontend may not be able to play, with no validation. → After download, verify the produced extension is in an allowlist (mp4/webm/mkv) and probe confirms a video stream before recording the entry. `backend/src/handlers/mod.rs:105-125`
494. 🟡 Two divergent media stores: library.json and SQLite - MediaEntry lives in a JSON file rewritten on each change while projects/jobs/cache live in SQLite with no shared id/FK, so the two stores can drift (e.g. a library entry whose output the cache also tracks) and there is no transactional boundary across them. → Migrate the library into a SQLite table with references to render_cache/outputs. `backend/src/library.rs:56-146`
495. 🟡 Audio codec/bitrate logic duplicated between push_audio and concat - The simple path uses push_audio (codec + 128k) while build_concat_args re-implements codec selection (webm->libopus, prores->pcm, else aac) and the 128k bitrate inline, so a future codec/bitrate change must be made in two places and can drift (prores skips -b:a in one path only). → Extract a shared push_audio_codec(format) helper used by both the single-pass and concat paths. `backend/src/tools/args.rs:191-206, 503-517`
496. 🟡 Single-pass av1/prores duplicate push_video_codec logic - The av1 and prores single-pass arms inline -c:v/-crf/-preset/-pix_fmt/faststart that are also defined in push_video_codec, so the two paths can silently drift (e.g. a future crf default change applied in only one place). → Route the av1/prores single-pass arms through push_video_codec like webm/mp4 do, keeping codec settings in one place. `backend/src/tools/args.rs:303-348, 381-402`
497. 🟡 tail() on ffmpeg/yt-dlp stderr can leak full local paths - On ffmpeg failure the last 15 stderr lines are returned verbatim in the job error (surfaced to the client), which can include absolute storage paths and internal filter strings, leaking server filesystem layout. → Map ffmpeg failures to a generic user message (like map_ytdlp_error does for yt-dlp) and log the raw tail server-side instead of returning it to the client. `backend/src/tools/mod.rs:287-288, 354-359`
498. 🟡 download_sections cuts are keyframe-approximate, undocumented - yt-dlp --download-sections with --merge-output-format mp4 trims at keyframes, so the imported start/end can differ from the requested seconds, but neither code nor README warns the user. → Document the approximation (or re-trim precisely with ffmpeg after download) so users aren't surprised by off-by-seconds imports. `backend/src/tools/mod.rs:92-101`
499. 🟡 Tests over-rely on fixed sleep-based polling (flake risk) - poll_terminal loops 400 times with 10ms sleeps (~4s budget) relying on the shared 2-permit semaphore and runtime scheduling; under a loaded CI runner a real-ffmpeg job could exceed the budget and panic 'never reached a terminal state', producing nondeterministic failures. → Increase/parameterize the budget for tool-backed tests, or switch to an event/notify-based wait instead of a fixed sleep count, and isolate per-test semaphores. `backend/tests/api.rs:89-103`
500. 🟡 Duplicated fmtDuration/fmtSize formatters across components - fmtDuration and fmtSize are copy-pasted in VideoPreview.vue and MediaLibrary.vue (and a fmt variant in EditPanel), so format/threshold fixes must be made in several places and can drift. → Extract shared time/size formatters into a single util module imported by all components. `frontend/src/components/VideoPreview.vue:91-102`
501. 🟡 History timer never flushed on export - doExport builds the payload from current state.edit while a recordChange may still be pending in historyTimer (350ms debounce); the exported edit is correct, but the in-flight change is not committed to history, so an immediate undo after exporting can skip the last tweak that was actually rendered. → Call a flush helper (if historyTimer recordChange()) at the start of doExport so history matches what was exported. `frontend/src/store.ts:265-298, 393-401`
502. 🟡 doImport edit reset can clobber a faster restore - After an import, defaults are set but restoreProject is never called (only openFromLibrary restores), so a freshly imported clip that already has a saved project (re-importing the same source url) ignores the saved edit and resets to defaults, then autosave overwrites the saved project with defaults. → Call restoreProject(v.id) after import too (or document that import intentionally starts fresh and skip autosave until the user makes a change). `frontend/src/store.ts:131-141`
503. 🟡 Preset save captures fps:null inconsistently - capturePreset copies fps (which may be null) into the preset; applyPreset then Object.assign sets state.edit.fps=null, which is the valid 'original' value, but because it is included it overrides a clip that had an explicit fps set, surprising the user who only meant to apply a colour look. → Decide whether fps is a 'look' attribute; if not, remove it from PRESET_KEYS so applying a look leaves the clip's fps intact. `frontend/src/store.ts:473, 488-493, 514-516`
504. 🟡 applyPreset spreads unknown keys onto state.edit - Object.assign(state.edit, p.edit) copies whatever keys the stored preset has; a preset saved by a newer version (or hand-edited localStorage) can inject arbitrary keys into state.edit, which then leak into autosave/snapshots and may confuse buildEditPayload's typed reads. → Whitelist the copy to PRESET_KEYS in applyPreset (iterate the known keys) instead of a blind Object.assign. `frontend/src/store.ts:514-517`
505. 🟡 buildEditPayload mute/speed always sent, others conditional - mute and speed are unconditionally included while every other effect is omitted at its default; this is harmless for the cache (backend re-serializes with defaults) but the asymmetry is undocumented and makes the 'send only what differs' comment (line 233) misleading for a reviewer. → Either send speed/mute only when non-default for consistency, or add a comment explaining they are always sent because the backend lacks a 'no audio change' sentinel. `frontend/src/store.ts:207-211, 234-256`
506. 🟡 history cap shift loses oldest without notice - history.past is capped at 100 via shift(), so the 101st change silently discards the oldest snapshot; combined with the 350ms debounce collapsing bursts this is usually fine, but there is no indication that deep undo history is bounded, and the cap is a magic number duplicated nowhere else. → Extract the cap to a named constant and document the bound; optional: only cap after flush so a single drag never trims more than one step. `frontend/src/store.ts:397-399`
507. 🟡 Project autosave watch is an unconditioned import side effect - Two deep watch() calls register at module import time with no init/teardown hook, so they cannot be disabled or mocked and leak across unit tests sharing the module (the history watch also fires timers). → Move watch registration into an explicit initStore()/composable invoked from main.ts and torn down in tests. `frontend/src/store.ts:440-447, 598-609`
508. 🟡 doImport/doUpload assign default edit then re-fire watchers - After a successful import/upload, state.edit is replaced and resetHistory() runs, but the autosave watcher still sees the new state.video+state.edit and schedules persistProject, immediately POSTing a brand-new project for a clip the backend already knows from the import, an avoidable write on every load. → Apply the same suppressAutosave guard around the post-import edit assignment, or have the import path mark the just-created clip as already-persisted. `frontend/src/store.ts:133-139, 182-188`
509. 🟡 Deep history watcher records geometry-only changes as steps - setTrimStartFromPlayer/setTrimEndFromPlayer and live crop drags mutate state.edit, each settling into its own debounced history step; a single drag of the crop overlay can emit one step but rapid hotkey nudges (ArrowLeft repeats) each restart the 350ms timer, so a long press collapses to one step while distinct deliberate nudges may merge unexpectedly. → Document the debounce coalescing behavior, and consider committing a history step on pointerup/keyup boundaries rather than a fixed 350ms window for deterministic step granularity. `frontend/src/store.ts:440-447, 324-332`
